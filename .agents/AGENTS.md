# Project-Scoped Rules for career-log

## 開発フロー (改訂版)

### 1. 本番に出す前に、必ずPreviewで確認する
- 修正は `main` に直接 push せず、作業ブランチ（例: `fix/follow-count`）を切ってそこに push すること。
- Vercel の Preview URL が発行されたら、その URL で下記チェックリストを確認してから、問題なければ `main` にマージすること。

### 2. 1回の修正は1テーマに絞る
- 「フォロー数」「投稿の反映」「表示の高速化」など、複数のテーマを1つのコミットにまとめないこと。
- 1つ直す → 動作確認 → 問題なければ次、の順番を徹底すること。

### 3. 変更のたびに確認する、最低限のチェックリスト
Firestore関連（ルール・データ構造）を変更した時は、毎回このチェックリストを実行すること：
- [ ] 新規登録 → プロフィールが表示される
- [ ] 投稿する → 自分のタイムライン・レポートにすぐ反映される（リロード不要）
- [ ] 別アカウントで、公開設定の相手をフォローする → フォロワー数がその場で増える
- [ ] フォローした相手のプロフィールを開く → 投稿一覧・レポートが表示される
- [ ] フォローを解除する → フォロワー数がその場で減る
- [ ] ブラウザの開発者ツール → Consoleに、`permission-denied` 等のエラーが出ていないか確認する

### 4. Firestoreルールを変更した時の注意
- ルールファイル（`firestore.rules`）を変更しただけでは反映されない。Firebaseコンソールで「公開」ボタンを押すまで無効。
- ルールを変更したら、上記チェックリストを必ず実行すること。
